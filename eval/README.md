# Harness-eval: проверяем, помогает ли автоправка AGENTS.md

Эксперимент в духе [google-research/harness2](https://github.com/google-research/harness2):
не берём фреймворк, берём метод. Задачи из истории репозитория гоняются агентом
(OpenCode CLI) с текущим `AGENTS.md`, потом модель-редактор предлагает правку
`AGENTS.md`, и те же задачи гоняются снова. Судья — гейт репозитория.

## Что измеряем

- Главное: доля задач, решённых агентом (целевые тесты прошли и новых падений нет).
- Побочное: нарушения правил проекта (правил тесты, не запустил гейт, юникс-команды
  в PowerShell).

## Устройство замера

1. **Задача** — fix-коммит из истории: меняет код и тесты. Песочница собирается на
   `fix^` (код до правки), тесты берутся из `fix` — целевые тесты падают, остальные
   проходят. Список целевых (FAIL_TO_PASS) считается эмпирически: `compute_targets`
   смотрит, что падает на базе и что после настоящей правки.
2. **Песочница** — клон репозитория без remote, с `opencode.json`, где опасные команды
   запрещены, и с нужным вариантом `AGENTS.md`.
3. **Прогон** — `opencode run --standalone --auto --model <модель> <задача>`.
   Сразу после агента снимается слепок песочницы: содержимое может быть снесено
   (OpenCode чистит `%TEMP%\opencode`, а туда нельзя класть артефакты).
4. **Судья** — `pytest -q` и `pyflakes` на слепке.

## Команды

```bash
python eval/harness_eval.py check                    # задачи валидны (целевые падают на базе)
python eval/harness_eval.py probe <fix-sha>:<tests>  # разведка кандидатов из истории
python eval/harness_eval.py run --task <id> --variant base
python eval/harness_eval.py run --task <id> --variant candidate --agents-md <файл>
python eval/harness_eval.py propose --base-dir <каталог с базовыми прогонами>
python eval/harness_eval.py report --out <каталог>
```

Артефакты пишутся в `%LOCALAPPDATA%\Lumen\harness-eval` (важно: не в `%TEMP%\opencode`).

## Ограничения

- Выборка маленькая (7 задач, по одному прогону на вариант) — это сигнал
  «есть/нет эффекта», а не статистика.
- Один и тот же агент решает задачи один раз: разброс между прогонами не измерен.
- Судья — гейт, он не ловит нарушения правил, если тесты всё равно прошли.
- MCP-серверы в песочнице отключены: прогоны быстрее и без сети, но это не ровно
  твоя обычная обстановка.
